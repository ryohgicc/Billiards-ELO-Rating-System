# Billiards ELO Rating System

一个免费、轻量的台球积分系统网站，适合球房、小群体或朋友局自己维护排行榜。

项目特点：
- 创建球员并维护启用/停用状态
- 录入两人胜负关系，自动按激进 `Elo` 计算积分
- 查看排行榜前三标识、比赛历史日期切换，并支持删除误录后自动重算
- 每天 0 点为启用球员生成公开透明的预约上场顺序
- 查看球员预览、AI 锐评、台球规则速查、训练小课和实战技巧
- 所有用户共享同一个 Cloudflare D1 数据库
- 支持导出/导入 JSON 备份
- 可部署到 Cloudflare Workers 静态资源站点

## 功能概览

### 1. 排行榜
- 按积分降序展示球员排名
- 显示积分、胜负场、胜率、最近比赛时间
- 前三名显示冠军、亚军、季军标识
- 支持总榜和按比赛日期查看历史排名快照
- 手机端卡片布局，桌面端表格布局

### 2. 球员管理
- 新建球员
- 防止重名
- 支持停用球员，避免误删导致历史数据失效
- 支持上传普通照片、胜利图片和失败图片，球员展示图会根据最近一场胜负自动切换

### 3. 比赛录入
- 选择胜者和负者
- 禁止同一球员对阵自己
- 录入后立即刷新积分榜
- 显示本场积分变化

### 4. 预约
- 每天本地时间 0 点为启用球员重新生成上场顺序
- 同一天同一批启用球员的顺序保持稳定，不写入数据库
- 每日名单把所有启用球员放进同一个候选池，再应用公开签号、活跃度加权和补偿规则
- 前一天最终垫底 2 人第二天优先排序
- 近 7 天活跃天数会带来小幅排序加权，同一天多场只算 1 个活跃日
- 近 7 天 0 活跃日球员只增加轻量排序惩罚，不再默认垫底
- 启用球员至少 3 人时，前 2 名不会和前一天最终前 2 名完全相同
- 第一、第二名从所有启用球员中产生；若昨天垫底 2 人仍启用，会先进入候选队列，再按当天加权签号和防重复规则排序
- 支持用公开日盐值和公开限定重置指定日期排序，当前 `2026-05-08` 使用 `reset-5`，且 `gjj` 不进入当天前 2 名
- 页面公开日期种子、签号和排序规则，方便复算验证

### 5. 比赛历史
- 支持按比赛日期切换查看历史
- 显示当天积分上升第一和下降第一
- 按时间倒序展示已录入比赛
- 展示 AI 锐评和双方赛后评价生成状态
- 支持删除单场比赛
- 删除后自动从历史回放并重算积分

### 6. 球员预览
- 在球探面板中按球员查看个人画像、战绩、成就和估值
- 支持从排行榜、球员管理页跳转到指定球员预览
- 展示完整比赛记录，以及按不同对手拆分的胜负和胜率分析
- 接入 AI 后展示当前称号、估值、评价、素材和最近比赛点评；素材保留赛况输入，不重复展示 AI 生成结果

### 7. 数据设置
- 修改站点标题
- 导出 JSON 备份
- 导入 JSON 恢复
- 清空当前浏览器中的本地数据
- 配置 AI 模型池和接口路由
- AI 后台生成请求最多等待 60 秒；小米 MiMo 模型会显式关闭 `thinking` 并使用 `max_completion_tokens`，返回结构不正确时最多重试 10 次，历史 AI 补生成会逐场同步处理

### 8. 台球学堂
- 规则速查
- 中 8 争议球处理
- 训练小课
- 实战技巧
- 今日台球小知识

## 积分规则

- 默认初始分：`1000`
- 默认 `K` 值：`70`
- 仅记录胜负，不记录比分
- 每场比赛结束后按激进 `Elo` 更新双方积分：同分胜负变化 `35` 分，低分击败高分时会按爆冷倍率额外放大，单场变化封顶 `160` 分
- 当前积分不写入数据库，而是从完整比赛历史按当前算法回放得出；调整算法或删除比赛后，历史胜负会自动重新计算排行榜
- 排名排序规则：
  - 先按积分降序
  - 同分时按胜率降序
  - 再按胜场降序
  - 最后按创建时间升序

## 部署

本项目已经配置：

```ts
output: "export"
```

同时包含 `wrangler.jsonc`，用于把静态文件和 Worker API 一起部署到 Cloudflare。

### Cloudflare Workers

推荐设置：
- Production branch: `main`
- Build command: `npm run build`
- Deploy command: `npx wrangler deploy`
- Root directory: `/`

首次部署前需要创建 D1 数据库，并把 `wrangler.jsonc` 里的 `database_id` 改成自己的数据库 ID。

然后执行远程数据库迁移：

```bash
npx wrangler d1 migrations list billiards-elo-db --remote
npm run db:migrate:remote
npx wrangler d1 migrations list billiards-elo-db --remote
```

第二次检查必须显示 `No migrations to apply`。如果 Worker 代码已经读取新表或新字段，但远程 D1 迁移还没应用，`/api/state` 会直接返回 500。

迁移成功后，Cloudflare 会发布 `out` 目录中的静态页面，并用 Worker 处理 `/api/*` 数据请求。

## 数据说明

当前版本使用 Cloudflare D1 作为共享数据库。

这意味着：
- 多个用户打开同一个网站会看到同一份排行榜
- 任意用户录入比赛后，刷新页面即可看到最新数据
- 推荐定期通过“数据设置”页面导出 JSON 做备份
- 当前版本还没有登录和权限控制，知道网址的人都可以编辑数据

## 适用场景

适合：
- 球房内部积分榜
- 朋友局长期排名

- 复杂权限管理
- 大型赛事管理
