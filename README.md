# Billiards ELO Rating System

一个免费、轻量的台球积分系统网站，适合球房、小群体或朋友局自己维护排行榜。

项目特点：
- 创建球员并维护启用/停用状态
- 录入两人胜负关系，自动按非对称 `Elo` 计算积分
- 查看排行榜前三标识、登顶/垫底天数、比赛历史日期切换，并支持编辑或删除误录后自动重算
- 每天 0 点为启用球员生成每日随机排序
- 查看球员预览、AI 锐评、台球规则速查、训练小课和实战技巧
- 提供 Slack 机器人战报接口，可按日期生成当日 Markdown 战报
- 所有用户共享同一个 Cloudflare D1 数据库
- 支持导出/导入 JSON 备份
- 可部署到 Cloudflare Workers 静态资源站点

## 功能概览

### 1. 排行榜
- 按积分降序展示球员排名
- 显示积分、胜负场、胜率、最近比赛时间
- 前三名显示冠军、亚军、季军标识
- 支持总榜和按比赛日期查看历史排名快照
- 显示当前名次较上一个有比赛日的上升、下降、不变或新上榜状态
- 按有比赛的日期快照统计每位球员的登顶天数和垫底天数，并在排行榜球员信息旁显示
- 首屏布局保持紧凑，桌面端会收紧顶部、榜首卡和表格行距，方便同时查看榜首概览与核心排名信息
- 手机端使用紧凑卡片布局，榜首概览、日期切换、球员照片、积分信息和历史长文案会适配窄屏展示；桌面端使用表格布局

### 2. 球员管理
- 新建球员
- 防止重名
- 支持停用球员，避免误删导致历史数据失效
- 支持上传胜利图片和失败图片，各保留 1 张；球员管理和预览页会以双图版式同时展示胜利/失败图片，排名页只使用胜利或失败图片

### 3. 比赛录入
- 选择胜者和负者
- 禁止同一球员对阵自己
- 录入后立即刷新积分榜
- 显示本场积分变化；终结对手 3 连胜及以上时，会显示额外的终结连胜奖励

### 4. 每日排序
- 每天本地时间 0 点为启用球员重新生成上场顺序
- 同一天同一批启用球员的顺序保持稳定，不写入数据库
- 预约页可回看从首位启用球员创建日到今天的每日排序历史，按日期切换查看每一天的顺序
- 历史日期使用横向滚动切换，桌面和手机都保留完整日期文本，排序表格只展示顺序和球员
- 每位启用球员只按当天日期、球员 ID 和创建时间生成随机签号，改名不会影响抽签结果
- 排序只看随机签号，极少数签号相同才用创建时间和球员 ID 兜底
- 不参考战绩、活跃天数、昨天名次、指定球员或任何补偿规则
- 页面公开日期种子和随机签号，方便确认当天排序来源
- `GET /api/reservation-order?date=YYYY-MM-DD` 可返回同一套排序 JSON；不传 `date` 时默认使用上海当天，响应包含 `dateSeed`、`drawSeed`、`algorithm` 和扁平化的 `entries`

### 5. 比赛历史
- 支持按比赛日期切换查看历史
- 显示当天积分上升第一和下降第一
- 按时间倒序展示已录入比赛
- 展示 AI 锐评和双方赛后评价生成状态
- AI 锐评会读取比赛标签的含义，并限制模型不要把未勾选标签、比分或额外剧情写成事实
- 支持编辑单场比赛的胜负方、精彩瞬间和双方备注
- 支持删除单场比赛
- 编辑或删除后自动从历史回放并重算积分，编辑会清理旧 AI 锐评等待后续重新生成

### 6. Slack 战报接口
- `GET /api/slack/battle-report?date=YYYY-MM-DD`
- 返回 `application/json`，日期按 `Asia/Shanghai` 解释；不传 `date` 时默认使用上海当天
- 响应包含 `message` 字段，可直接交给 Slack 机器人发送；同时返回 `matches` 逐场明细和 `records` 当日胜负榜
- `matches` 中会返回 `streakBreakerBonus` 和 `winStreakBonus`，文案也会标注终结连胜奖励和连胜延续奖励
- 单场积分变化、赛后积分和当日榜单都从历史比赛按自然月回放重算，不写入数据库

示例：

```bash
curl -H "Accept: application/json" "https://your-domain.example/api/slack/battle-report?date=2026-06-23"
```

### 7. 球员预览
- 在球探面板中按球员查看个人画像、战绩、成就和估值
- 支持从排行榜、球员管理页跳转到指定球员预览
- 展示完整比赛记录，以及按不同对手拆分的胜负和胜率分析
- 接入 AI 后展示当前称号、估值、评价、素材和最近比赛点评；素材保留赛况输入，不重复展示 AI 生成结果

### 8. 数据设置
- 修改站点标题
- 导出 JSON 备份
- 导入 JSON 恢复
- 清空当前浏览器中的本地数据
- 配置 AI 模型池和接口路由
- AI 后台生成请求最多等待 60 秒；小米 MiMo 模型会显式关闭 `thinking` 并使用 `max_completion_tokens`，返回结构不正确时最多重试 10 次，历史 AI 补生成会逐场同步处理
- AI 赛后 prompt 会传入精彩瞬间标签解释和事实边界，让锐评更贴近实际勾选内容

### 9. 台球学堂
- 规则速查
- 中 8 争议球处理
- 训练小课
- 实战技巧
- 今日台球小知识

## 积分规则

- 每个自然月是一个独立赛季，所有球员每月从 `1000` 分重新开始
- 默认 `K` 值固定为 `100`（中段球员），页面和 Worker 都会忽略数据库中遗留的旧 K 值设置；新人段 `150`、稳定段 `50`，按本月比赛总场数分段（借鉴 FIDE 国际象棋）
- 仅记录胜负，不记录比分
- 每场比赛按标准 Elo 期望值计算，胜负双方各自使用自己的赛前积分、对手赛前积分和自己的赛前 K 值；败方扣分会根据分差动态调整扣分系数（范围 0.1 至 0.9），因此加扣分不再守恒：
  - **同分对局**：分差为 0 时扣分系数 = 0.50，中段 K=100 时胜方加 `50`、败方扣 `25`；新人 K=150 时变化 `+75/-38`；稳定 K=50 时为 `+25/-13`
  - **弱输强极少扣**：弱者输给强者时，分差为负，扣分系数降至约 0.1-0.3，实际扣分极少（如分差 -400 时系数约 0.32，仅扣 -3 分）
  - **强输弱重扣**：强者输给弱者时，分差为正，扣分系数升至约 0.7-0.9，实际扣分很多（如分差 +400 时系数约 0.68，扣 -62 分）
  - **强输弱多扣**：强者输给弱者时，分差为正，扣分系数升至约 0.6-0.7，实际扣分更多（如分差 +400 时系数约 0.59，扣 -54 分）
  - **低分爆冷**：胜方按 `胜方K × (1 − 胜方预期胜率)` 获得高额奖励；高分败方按动态系数承受更重扣分
  - **终结连胜奖励**：当败方赛前至少 `3` 连胜时，胜方额外获得 `round(胜方K × 0.05 × (败方赛前连胜 − 2))`；奖励不封顶，只加给胜方，败方不额外扣分
  - **连胜延续奖励**：当胜方获胜后达到至少 `3` 连胜时，胜方额外获得 `round(胜方K × 0.03 × (胜方赛前连胜 − 1))`；可与终结连胜奖励叠加，败方不额外扣分
  - **非守恒变化**：单场胜者加分总是大于败者扣分，总分逐渐增加；双方 K 不同则继续按各自 K 值拉开
  - 取消单场 `±160` 限制，极端强弱局可能四舍五入为 `0` 分变化
- 当前积分不写入数据库，而是从比赛历史按自然月分组回放得出；新增、编辑、删除比赛或调整算法后，对应月份的 `winnerDelta`、`loserDelta`、最终积分、规则成就和规则称号都会重算
- 排行榜提供月度归档，每月保留该月最后一个比赛日的快照；历史比赛记录保留完整数据，不被新赛季重置
- 排名排序规则：
  - 先按积分降序
  - 同分时按胜率降序
  - 再按胜场降序
  - 最后按创建时间升序

## 部署

本项目已经配置：

```ts
output: "export"
```

同时包含 `wrangler.jsonc`，用于把静态文件和 Worker API 一起部署到 Cloudflare。

### Cloudflare Workers

推荐设置：
- Production branch: `main`
- Build command: `npm run build`
- Deploy command: `npx wrangler deploy`
- Root directory: `/`

首次部署前需要创建 D1 数据库，并把 `wrangler.jsonc` 里的 `database_id` 改成自己的数据库 ID。

然后执行远程数据库迁移：

```bash
npx wrangler d1 migrations list billiards-elo-db --remote
npm run db:migrate:remote
npx wrangler d1 migrations list billiards-elo-db --remote
```

第二次检查必须显示 `No migrations to apply`。如果 Worker 代码已经读取新表或新字段，但远程 D1 迁移还没应用，`/api/state` 会直接返回 500。

迁移成功后，Cloudflare 会发布 `out` 目录中的静态页面，并用 Worker 处理 `/api/*` 数据请求。

### Cloudflare 免费加速建议

朋友内部使用、不备案时，推荐继续使用 Cloudflare 免费版，并在控制台确认：
- DNS 记录保持橙云代理
- 开启 Brotli 压缩
- 开启 HTTP/3
- 开启 Early Hints
- 为 `/_next/static/*` 配置长期 immutable 缓存，为 HTML 入口配置 `no-cache`
- 为 `/api/*` 配置跳过缓存，避免录入比赛后数据长时间不刷新

仓库里的 `public/_headers` 已经为 Next.js chunk、静态资源和 HTML 配置了缓存兜底；带 hash 的 `/_next/static/*` 使用长期 immutable 缓存，HTML 入口使用 `no-cache` 以便每次校验最新构建引用，避免长期使用 `Clear-Site-Data` 反复清空浏览器缓存；`/api/state` 在 Worker 内有 10 秒短缓存，并会在写入后清理。更详细的免费加速清单见 `docs/deployment/cloudflare-free-acceleration.md`。

## 数据说明

当前版本使用 Cloudflare D1 作为共享数据库。

这意味着：
- 多个用户打开同一个网站会看到同一份排行榜
- 任意用户录入比赛后，刷新页面即可看到最新数据
- 推荐定期通过“数据设置”页面导出 JSON 做备份
- 当前版本还没有登录和权限控制，知道网址的人都可以编辑数据
